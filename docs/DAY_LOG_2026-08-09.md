### Fable Brief II — corrected salience formula
- **Why**: The original brief-I formula was
  `S = w₁·log(density) + w₂·Σᵢ(t−tᵢ)⁻ᵈ + w₃·spread + w₄·max-sim`. Fable
  caught that `density` and the recency sum double-counted the same
  evidence — in ACT-R, occurrence count IS the number of terms in the
  sum.
- **What shipped**: Formula corrected to
  `S = ln(Σᵢ(t−tᵢ)⁻⁰·⁵) + spread + goal_overlap`. Documented in
  `docs/SALIENCE_FORMULA.md`.
- **Learned**: The 1991 spine (Anderson & Schooler) is right, but naive
  translation into the MVP double-counted.

## Late morning — Builds 1+2

### Build 1 — case-blind extraction + self-corpus stoplist
- **Why**: v001 top-10 was all entities (`claude`, `mikai`, `wiki`,
  `graphiti`, `brian`, `apple`, `claude-code`, `gmail`, `martin`).
  Recall@10 = 1/10 because Brian's gold-list concepts (`posture`,
  `workout`, `parents`, `startup`, `proposal spot`) were all lowercase
  — and the capitalized-only regex excluded them entirely.
- **What shipped**: Added lowercase 1-3 word n-gram extraction (freq
  ≥ 15) alongside the existing capitalized pass. Added self-corpus
  stoplist auto-generated from repo file/dir names to counter the
  MIKAI-eats-its-own-tail bias.
- **Learned**: Extraction ceiling lifted (`posture` and friends became
  candidates) but conversation-vocab flooded top-20 (`assistant`,
  `session`, `thread`). Extraction was too permissive.

### Build 2 — deterministic alias folding (E1-lite)
- **Why**: v001 ledger had `claude` (rank 1), `claude-code` (rank 8),
  and `Claude Code` (rank 18) all promoted as separate pages for the
  same thing. Canonicalization tax visible in the top 20.
- **What shipped**: `_alias_key` normalizes case + hyphen/space + plural
  → alias key. `_fold_aliases` groups by key. Head candidate keeps type;
  others become aliases. Ontology entries win as heads.
- **Learned**: Modifier-variant folding (`Mint Monstera` → `monstera`)
  was deferred to v1 — needs Voyage embedding cosine per Fable's spec.

### Build 2.5 — multiprocessing scoring
- **Why**: First Build 1 dry-run took 40+ min single-threaded. Killed
  twice by session teardowns.
- **What shipped**: `multiprocessing.Pool` over 8 workers, records list
  pickled to workers via `initializer`. `imap_unordered` for streaming
  progress.
- **Learned**: Perf dropped from ~40 min to ~18 min (2-3x, not the 4-6x
  I predicted). File I/O contention + pool startup cost. `nohup` +
  `disown` also added to survive future session teardowns.

## Afternoon — Eval harness + Build 3

### `eval/salience_recall.py` + `plot_salience.html`
- **Why**: Every architecture change was being "graded by squinting
  at top-20." No metric. Fable's earlier brief said: gold-set + recall
  metric + regression check per version.
- **What shipped**: Reads `GOALS.md` (10 goals) + `wiki-salience.md`
  → computes recall@10/@20/@50 + MRR + NDCG@10. Writes dated report
  + `eval/history.jsonl` + regenerates inline-SVG `plot_salience.html`
  dashboard.
- **Learned**: v001 measurement = 0.10 recall@10 (only MIKAI at rank 2).
  Baseline established.

### `docs/SALIENCE_VERSION_HISTORY.md` + 3-metrics rule
- **Why**: Need a rule that survives version drift.
- **What shipped**: Every substantive change gets a row + 3 metrics
  (consolidation quality, retrieval quality, summary faithfulness).
  Regressions flagged with reasoning.
- **Learned**: Only consolidation quality is automated so far;
  retrieval + faithfulness deferred to v0.2.

### Build 3 — S/G split with GOALS.md + G-axis
- **Why**: Fable's post-MVP diagnostic named the construct-validity
  failure: S measures "what recurs," Brian's gold measures "what
  matters." No amount of tuning fixes the corpus/gold mismatch.
- **What shipped**: `~/.mikai/brain/GOALS.md` hand-authored with
  Brian's 10 gold concepts. `_compute_g_cosine` computes G(c) = TF
  cosine between candidate mention-contexts and each goal. Ledger
  gained G column + goal-evidence gap section. Promotion changed to
  UNION of top-K by S ∪ top-K by G.
- **Learned**: G-axis fired correctly (top gold concepts got G > 0)
  but G column collapsed to 0.03–0.11 noise band. Binary token-set
  cosine denominator dominated by context-set size, not topical
  alignment. G-axis needs embedding-based similarity to matter.

## Late evening — Builds 5, 6, 7 + L3/L4 boundary fix

### Build 5 — `ingest_source.py` (per-source LLM extraction)
- **Why**: MIKAI ingests each source as ONE wiki.md row. Never LLM-
  extracts. Karpathy's `/ingest-url` operation compiles one URL into
  5-15 wiki pages via write-time LLM routing.
- **What shipped**: New module. For each new wiki.md section: one LLM
  call = "which existing concepts does this touch? suggest new
  pages." State tracked at `.ingest-source-state.json`. Suggestions
  land in `~/.mikai/wiki/concept-inbox.md`.
- **Learned**: First 5-source test — 1 apple-note touched 3 concepts
  + suggested 5 new. 4 others correctly touched 0. Mechanism works.
  15-source real run (PID 42297) processed a batch, state advanced.

### Build 6 — `ingest_source --catchup` (backlog mode)
- **Why**: Build 5 forward mode only handles NEW material. Old wiki.md
  backlog (~8000 sections) never gets Build 5 treatment.
- **What shipped**: Added `--catchup` flag. Iterates OLDEST unprocessed
  sections up to max-sources. Tracks `catchup_ts` separately from
  `last_processed_ts`. Complementary cursors.
- **Learned**: 3-source real catchup test — 2013-2014 Apple Notes
  correctly touched 0 concepts (predate MIKAI vocabulary). State
  advanced to `catchup_ts=2014-05-11`.

### Build 7 — `dream_lint.py` (health checks)
- **Why**: Karpathy's `/lint-wiki`. MIKAI had zero broken-link check,
  no orphan detection, no goal-gap surfacing.
- **What shipped**: Scans `~/.mikai/wiki/concepts/*.md`. Detects broken
  wikilinks, orphan pages, goal-evidence gaps (per goal in GOALS.md,
  how many matching concept pages?), inbox review count. Report
  written to `~/.mikai/wiki/concepts/lint-report-YYYY-MM-DD.md`.
- **Learned**: 27 broken wikilinks (all pointing to goal names, not
  concept pages) + 9/10 goals have zero matching concept page.

### L3/L4 boundary fix (post-lint)
- **Why**: Lint revealed 27 broken wikilinks were `[[mikai-and-ambient-
  computing]]` — a GOAL name, not a concept page. Build 4's template
  was wikilinking to goal slugs. Layer violation.
- **What shipped**: `karpathy_rerender.py` updated: goal names in Why
  section render as backticks (L4 metadata display), not `[[wikilinks]]`
  (L3 link graph). Aliases in Notes removed entirely — they belong in
  frontmatter, and their pluralized forms don't map to real pages.
- **Learned**: Rule for future page-writers: L3 wikilinks only to
  other L3 concept pages. L4 metadata in frontmatter or backticks.
  Never L4 as wikilink target. Broken-link count: 27 → 0.

### Fable brief on semantic-clustering gap
- **Why**: v004 eval still 0.00 recall@10. Ran mikai_ask on posture —
  came back with fragments. Realized the whole extraction pipeline
  operates on strings, has no concept of "thread" as a unit.
- **What Fable named**: The 5th primitive **E5 = Semantic assignment**
  — embedding-space membership map from content units (threads,
  notes) to concepts. Weighted Yoga thread has 803 turns concentrated
  in ONE thread → spread=2 → S penalizes exactly the property that
  makes it a real topic.
- **Documented**: `docs/SEMANTIC_CLUSTERING_GAP.md` (14 KB, 5 sections).
