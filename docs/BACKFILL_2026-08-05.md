## Real-run stats

- **Written: 8,048** (3 in a `--limit=5` smoke run + 8,045 in the full run)
- **Skipped: 372 true duplicates** (identical header AND identical
  content byte-count — double-ingest artifacts in Neo4j). 4 of the 376
  header-duplicates had *different* content and were written, correctly.
- **Errors: 0**
- Written per source (both runs combined): claude-code 3,537 /
  claude-thread 1,932 / perplexity 1,488 / apple-notes 1,053 /
  strategic-synthesis 33 / gmail 2 / whatsapp-day 2 / claude 1
- Chronological order preserved: 8,047 of 8,048 sections are in strict
  `reference_time` order. The single exception is one
  strategic-synthesis episode whose `valid_at` was stored *naive* (no
  timezone) in Neo4j — Neo4j's `ORDER BY` sorts naive datetimes after
  zoned ones, so it landed at the file tail. Its header still carries
  the correct date (`2026-06-14T18:43:24.130868`), which is what dream
  windows on, so it is cosmetic only.
- Idempotency verified: an immediate re-run wrote 0 episodes, +0 bytes.

## Flags

- `wiki.md` is now ~27 MB — far past the 120 KB `MIKAI_WIKI_MAX_CHARS`
  read cap in `WikiAdapter._read_wiki_bundle()`. Adapter reads truncate
  to the head of the file (hand-curated ontology + oldest episodes).
  Anything that consumes the wiki whole (FIGS tick, cockpit) sees only
  the cap window; dream's 7-day windowing must select sections by header
  timestamp, not read the bundle. Compaction / windowed reads are the
  obvious next pass.
- Backfilled content is distinguishable from live-ingested content by
  the `ingested=2026-08-06T04:4…` comment timestamps.
