## The pattern

**Sumimasen** is MIKAI's *delivery gate* principle: an AI system "earns the right to interrupt by demonstrated utility rather than interrupting on a fixed schedule" (`concepts/sumimasen`). The name is the Japanese polite excuse-me — the agent announces itself only when it has genuine cause.

Its structural claim is that interruption carries a **trust cost proportional to the irrelevance of the interruption**, so each surfacing is a debit that must be covered by demonstrated relevance (`concepts/sumimasen`, framed there against a productivity/proactivity/personalization objective). It is the explicit inverse of cron-based proactivity: `entities/openclaw`'s HEARTBEAT.md fires because the clock advanced; Sumimasen fires because *thread state changed* and the change clears a utility threshold. `entities/chatgpt-pulse`'s admitted failure — resurfacing completed projects — is named as the HEARTBEAT.md failure mode at platform scale.

Two dependencies the pages make explicit:

- **Upstream state.** Sumimasen sits at S4 (Thalamus / delivery gate) in `concepts/second-brain-strata`, and cannot make a utility judgment until S3 — `concepts/thread-state-machine`, MIKAI's L4 / D-041 — has classified a thread as active/stalled/closed.
- **Downstream contract.** At the LLM layer, the gate is implemented as a `concepts/strict-intervention-contract`: the model's *default* output is `{"interject": false}`, and it may return `true` only for three enumerated triggers — an unanswered factual question, a materially wrong factual claim, or a stall caused by missing knowledge. The insight there is that enumerating trigger conditions works where instructing the model to "only intervene when important" does not.

## The one concrete implementation

`sources/2026-08-02-ai-as-a-conversational-research-partner-dec921` records the ~1-hour Sumimasen MVP — a React/Web Speech API webapp for café-and-car conversations. It layers two gates:

1. **Reticence control** (upstream, cheap): don't even query the model until ~14+ new words *and* ~2.6 s of silence; a reserved/balanced/eager setting tunes the word threshold and cooldown. Per `concepts/strict-intervention-contract`, this "reduces unnecessary API calls" while the contract "ensures that queries that do reach the model produce minimal false positives."
2. **The strict contract** (at the model): the three triggers above, over the last ~1,600 chars with web search on.

Output is a soft rin bell plus a glanceable card in an `concepts/andon-design` idiom — "the phone on the table should not glow — it should only signal." The chime is push, viewing the card is pull (`concepts/push-vs-pull-architecture`). Web search adds 5–15 s, accepted as latency-bounded relevance.

## Where it applies

- **The MVP source explicitly generalizes back:** "the reticence control, strict intervention contract, and push/pull split are directly transferable to MIKAI's ambient-agent notification design."
- **Beyond informational surfacing.** `concepts/consequence-weighted-action-gate` extends the binary surface-or-silence decision (Tier 1) across `concepts/action-tier-hierarchy`: `act iff expected_value > reversibility_weight(tier) × confidence_threshold(tier)` — dismiss-rate metric at Tier 1, reversibility-weighted confidence at Tier 2 (digital/transactional), human-in-the-loop approval at Tier 3 (cyber-physical).

It reads the whole pattern as an instance of `concepts/human-on-the-loop` posture — the human's flow is the primary process, the agent subordinate and constrained.

## The pattern

**Sumimasen is a reticence gate: default to silence, and interrupt only when the case for interrupting is strong on two independent axes at once.** It's named after the Japanese expression for a polite, minimally intrusive apology for an interruption (`concepts/sumimasen-gate`, `entities/sumimasen-app`).

The load-bearing justification is an **asymmetric trust cost**: a false positive (interrupting when it wasn't warranted) "burns trust in the automation pipeline in a way that a missed suggestion does not." So the gate is biased strongly toward silence — false negatives are the cheaper error (`concepts/sumimasen-gate`).

Its canonical form requires two simultaneous conditions:
1. **High redundancy** — the cluster metric crosses a meaningful threshold, not marginal overlap.
2. **High confidence** — the detector is certain the items belong together.

A second structural property: the gate runs on **cheap statistics before any LLM call**, so it's a cost filter as well as a politeness filter (`concepts/sumimasen-gate`).

## Where it applies

**1. Thread consolidation / triggered compaction.** In the `concepts/triggered-compaction` automation, "every auto-proposal is a Sumimasen transaction" — only when both conditions hold does the pipeline surface "these threads should be consolidated" (`concepts/sumimasen-gate`).

**2. Here the gate is instantiated as:
- A **dual trigger**: ≥14 new words *and* ≥2.3 seconds of silence — the same two-axis structure, tuned for conversational timing.
- A **strict three-condition contract** at the prompt layer: return `{"interject": false}` unless there's (1) an unanswered factual question, (2) a materially wrong claim, or (3) a stall on missing knowledge.
- A **"Restraint" dial** (reserved / balanced / eager) adjusting word threshold and cooldown — "the hospitality philosophy as a numeric dial."

**4. As a member of the JITAI family.** The gate is "the same family of mechanism" as `concepts/jitai` and `concepts/timing-intelligence` — an interruption-worthiness decision weighing intervention value against interruption cost — but instantiated for *knowledge management* rather than behavioral nudging (`concepts/sumimasen-gate`). `concepts/attention-economics` supplies the underlying value-of-information framing.

Per `concepts/mikai-l4-state-machine`, classification is the middle stage of a three-step pipeline that runs identically regardless of how the thread entered:

**detect thread → classify state → infer next step**

`concepts/thread-state-machine` decomposes the same layer (also called D-041) into three separable subproblems, of which classification is the first:

## First, a framing correction the substrate insists on

The vault does **not** organize memory architecture as a linear generation ladder (pre-LLM → RAG → memory products). Its primary frame — `sources/2026-08-07-memory-architectures-across-software-history-fd56b8` — is **five parallel lineages** running 1945→present, with the LLM era as a *simultaneous repricing of all five*, not a successor to them. RAG is not a generation; it's the terminal node of one branch inside Lineage 2 (`Salton's SMART → IDF → BM25 → RAG`).

The central claim: **the only genuinely new component in the LLM era is the *reader*** — a component that can consume loosely structured state and act on it. Everything else sold as "LLM memory" is a re-derivation of one of the five older lineages, and each lineage carries a predictable failure mode.

## The five lineages

| # | Lineage | Span | Canonical line | LLM-era re-derivation |
|---|---|---|---|---|
| 1 | Memory as **scarcity** | 1945–1980s | von Neumann → Atlas virtual memory (1962) → Denning working set (1968) | Context window = working set; context assembly = paging. MemGPT self-describes as OS-style virtual context management. |
| 2 | Memory as **record** | 1960s–2010s | IMS (1968) → Codd (1970) → ARIES (1992); temporal DBs (Snodgrass, SQL:2011); IR branch SMART → BM25 → **RAG** | Event sourcing, Kafka, Graphiti's episode store. Zep's bitemporality is a rediscovery of valid-time vs transaction-time. |
| 3 | Memory as **meaning** | 1966–2012 | Quillian semantic networks → Minsky frames (1975) → Schank *Dynamic Memory* (1982) | Letta memory blocks are frames; case-based reasoning is few-shot prompting with a database, twenty years early. Died of the [[knowledge-acquisition-bottleneck]]. |

## The gating constraint

## Near-term: architectures that need no labels

**L4 — Hawkes process** (`concepts/hawkes-process`). Called "the sleeper pick." Each thread's timestamped episode stream is a self-exciting point process, λ(t) = μ + Σᵢ φ(t − tᵢ). High λ(t) → thread is `acting`; decay toward μ → `stalled`. The fitted 90th-percentile inter-event interval gives an *expected next-event time*, which replaces the arbitrary N-day stall window with a principled threshold. Parametric Hawkes has few parameters and fits on minimal data — essentially a zero-LLM statistical model, which the source ties directly to the O-036 design philosophy.

Upgrade path once the parametric form is too rigid: **neural TPP variants — RMTPP, Transformer Hawkes** (`concepts/temporal-point-process` also names neural Hawkes and intensity-free variants as candidates for the "when will this resurface?" sub-problem).

**L3 — self-supervised structural graph embeddings** (`concepts/self-supervised-graph-representation-learning`): node2vec, Deep Graph Infomax, unsupervised GraphSAGE. These encode topological position with no labels, complementing Voyage's semantic embeddings. The concrete payoff per `concepts/structural-vs-semantic-embeddings`: the hand-tuned `boost` constant in FOUNDATIONS §3 (0.08 → 0.12) is a proxy for a learned structural signal — the embeddings let it be *learned* rather than set by hand.

**L3 — retrieval-side (not strictly neural-architecture):** multi-scale embedding at 128/256/512 granularity with Reciprocal Rank Fusion, and possibly ColBERT-style late interaction for short transactional segments.

**Everything else:** gradient-boosted trees (XGBoost/LightGBM) or rule-based, per D-026.

## Long-term: unlocked by multi-user labels

Per `concepts/temporal-graph-networks`, **TGN** (Rossi et al. 2020, per-node memory updated by message-passing on each interaction) and **TGAT** (Xu et al. 2020, time-encoding + attention over temporal neighborhoods) are called "the architecturally correct model" for `entities/graphiti`'s bitemporal graph — valid-time and transaction-time on every edge, edges invalidated rather than deleted. TGN would *unify* L3 structure and L4 temporal dynamics, which are currently separate heuristics.

Then **supervised GNN link prediction**, which is the ML-native form of `concepts/intention-behavior-gap`: a stated-intent node in Track A with no semantically-adjacent action node in Track B is a missing edge a model can learn to flag. Near-term this stays a heuristic gated on the Hawkes-derived expected window. Then the **PPP RL loop**, already deferred.

```
Now:   Hawkes (per-thread, parametric, zero labels)

## The short answer

The substrate's most direct treatment of this question is `sources/2026-07-01-neural-networks-for-mikai-graph-inference-572b84`, which reframes it: the binding constraint isn't which architecture is best in the abstract, it's that MIKAI sits in a **label-scarce regime** (~12,600 entities, ~20–30 planned labeled threads) that is "actively hostile to supervised deep learning" (`concepts/label-scarce-regime`). So the answer splits into *build now* (unsupervised) vs. *defer* (supervised/temporal-graph).

## Build now — two architectures fit today

**1. Self-supervised graph representation learning (L3 / graphing layer)**
node2vec, Deep Graph Infomax (DGI), or unsupervised GraphSAGE produce node embeddings from topology alone, no labels required (`concepts/self-supervised-graph-representation-learning`). The payoff is specific: these are *structural* embeddings — where a node sits in the graph — and are complementary to Voyage's *semantic* embeddings of what a node means (`concepts/structural-vs-semantic-embeddings`). MIKAI currently hand-weights that hybrid with tuned constants; structural embeddings let the weighting be learned instead of manually calibrated.

**2. Classical Hawkes process / temporal point process (L4 / inference layer)**
Called the "sleeper pick" in the source. Per thread, each timestamped episode raises the intensity λ(t) of near-term future events, then decays — which yields a principled stall threshold ("past the 90th percentile of this thread's inter-event interval") instead of an arbitrary N-day window (`concepts/temporal-point-process`). Classical Hawkes is a handful of parameters, fits on minimal data, and is essentially a zero-LLM statistical model.

Also flagged as higher-leverage than swapping models: **multi-scale embedding with Reciprocal Rank Fusion** — embed at 128/256/512 token granularities and fuse the rankings.

Everything else stays rule-based or gradient-boosted trees per D-026.

## Defer to multi-user scale

- **Temporal Graph Networks (TGN / TGAT)** — described as the architecturally correct future-state model.
